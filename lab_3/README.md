## MPI-алгоритм

В данной лабораторной работе используется распределение по строкам результирующей матрицы `C`.

Формально элемент матрицы результата вычисляется как:

```text
C[i][j] = sum_{k=0}^{N-1} A[i][k] * B[k][j]
```

В одномерном представлении:

```text
C[i*N + j] += A[i*N + k] * B[k*N + j]
```

Для параллельного выполнения матрица `C` делится по строкам между MPI-процессами.

Например, для `N = 200` и `P = 4`:

```text
процесс 0: строки 0..49
процесс 1: строки 50..99
процесс 2: строки 100..149
процесс 3: строки 150..199
```

Каждый MPI-процесс получает:

- свой фрагмент строк матрицы `A`;
- полную матрицу `B`.

После этого каждый процесс вычисляет свою часть матрицы `C`.

Используемые MPI-операции:

```cpp
MPI_Scatterv
MPI_Bcast
MPI_Gatherv
MPI_Allreduce
MPI_Wtime
```

Где:

- `MPI_Scatterv` рассылает строки матрицы `A` по процессам;
- `MPI_Bcast` транслирует матрицу `B` всем процессам;
- `MPI_Gatherv` собирает результат на процесс `rank 0`;
- `MPI_Allreduce` используется для определения максимального времени выполнения среди процессов;
- `MPI_Wtime` используется для замера времени параллельного вычисления.

---


### `speedup_vs_sequential`

Ускорение параллельной MPI-версии относительно baseline.

В данной работе в качестве baseline использовалась та же MPI-программа, запущенная с одним процессом:

```text
P = 1
```

Формула:

```text
speedup = T_baseline / T_parallel
```

где:

- `T_baseline` — время выполнения MPI-программы с одним процессом;
- `T_parallel` — время выполнения MPI-программы с `P` процессами.

Идеальное ускорение для `P` процессов:

```text
speedup = P
```

## Анализ результатов

### 1. Сохранение кубической сложности

Как и в последовательной версии, общее количество операций не меняется:

```text
2*N³ - N²
```

MPI не изменяет асимптотическую сложность алгоритма, но позволяет распределить вычисления между несколькими процессами.

Поэтому время выполнения всё равно растёт примерно как:

```text
O(N³)
```

но с меньшей константой за счёт параллельного выполнения.

---

### 2. Ускорение близко к линейному

Для двух процессов идеальное ускорение равно:

```text
2
```

Фактические значения:

```text
1.87–2.00
```

Для четырёх процессов идеальное ускорение равно:

```text
4
```

Фактические значения:

```text
3.51–3.95
```

Это означает, что основная часть времени приходится на полезные вычисления, а накладные расходы MPI относительно невелики.

---

### 3. Высокая эффективность

Эффективность показывает, насколько рационально используются процессы:

```text
efficiency = speedup / processes
```

Для четырёх процессов эффективность составила:

| N | Efficiency P=4 |
|---:|---:|
| 200 | 0.950 |
| 400 | 0.946 |
| 800 | 0.986 |
| 1200 | 0.954 |
| 1600 | 0.878 |
| 2000 | 0.938 |

В среднем эффективность близка к `0.95`, что является хорошим результатом.

---

### 4. Причина отклонения на N=1600

Наиболее заметное снижение эффективности для 4 процессов наблюдается при:

```text
N = 1600
```

Speedup составил:

```text
3.511
```

Эффективность:

```text
0.878
```

Возможные причины:

- увеличение объёма транслируемой матрицы `B`;
- влияние сетевой подсистемы узла;
- кэш-эффекты;
- фоновая загрузка кластера;
- особенности размещения процессов на ядрах.

Поскольку в используемой схеме каждый процесс получает полную матрицу `B`, объём коммуникаций растёт как:

```text
O(N²)
```

а объём вычислений на процесс — как:

```text
O(N³ / P)
```

Поэтому на достаточно больших `N` коммуникационная составляющая обычно становится менее заметной, однако локальные флуктуации всё равно возможны.

---

### 5. Влияние схемы декомпозиции

Использована простая и эффективная схема — распределение по строкам матрицы `C`.

Преимущества:

- каждый процесс вычисляет независимый блок результата;
- нет гонок данных между процессами;
- не требуется синхронизация во время вычислений;
- сборка результата выполняется одной операцией `MPI_Gatherv`.

Недостатки:

- каждому процессу нужна полная матрица `B`;
- для очень больших матриц это может увеличивать потребление памяти и объём коммуникаций.

Для размеров до `2000 × 2000` такая схема работает хорошо.

В лабораторной работе №3 используется MPI-версия, где параллелизм реализуется на уровне отдельных процессов.
