## Используемая задача

В качестве экспериментальной задачи используется операция перемножения двух квадратных матриц:

```text
C = A × B
```

где:

- `A` — матрица размера `N × N`;
- `B` — матрица размера `N × N`;
- `C` — результирующая матрица размера `N × N`.

Классический алгоритм умножения матриц имеет асимптотическую сложность:

```text
O(N³)
```

Количество арифметических операций приблизительно равно:

```text
2*N³ - N²
```

то есть:

- `N³` умножений;
- `N² * (N - 1)` сложений.

## Параллельный алгоритм

В данной лабораторной работе используется распараллеливание по строкам результирующей матрицы `C`.

Формально элемент матрицы результата вычисляется как:

```text
C[i][j] = sum_{k=0}^{N-1} A[i][k] * B[k][j]
```

В одномерном представлении:

```text
C[i*N + j] += A[i*N + k] * B[k*N + j]
```

Для параллельного выполнения используется директива OpenMP. Она распределяет внешний цикл по строкам матрицы `C` между потоками.

Пример:

```cpp
#pragma omp parallel for schedule(static)
for (int i = 0; i < n; ++i)
{
    for (int k = 0; k < n; ++k)
    {
        int aik = a[i * n + k];

        for (int j = 0; j < n; ++j)
        {
            c[i * n + j] += aik * b[k * n + j];
        }
    }
}
```

Такой способ распараллеливания безопасен, потому что каждый поток записывает данные только в свою строку матрицы `C`. Гонок за память при этом не возникает.

## Пояснение полей отчёта(здесь будут описаны только новые, по сравнению с отчётом из лабораторной №1, поля)

### `threads`

Количество потоков OpenMP, фактически использованных при выполнении.

---

### `speedup_vs_sequential`

Ускорение параллельной версии относительно последовательной.

Считается по формуле:

```text
speedup = T_sequential / T_parallel
```

---

### `efficiency`

Эффективность параллельного выполнения.

Считается по формуле:

```text
efficiency = speedup / threads
```

## Анализ результатов

В ходе экспериментов исследовалась зависимость времени выполнения от размера матрицы и количества потоков OpenMP.

### 1. Сохранение кубической сложности

Для каждого фиксированного количества потоков время выполнения по-прежнему растёт примерно как:

```text
T(N) = O(N³)
```

Это означает, что параллеливание уменьшает константу времени выполнения, но не меняет асимптотическую сложность алгоритма.

Если увеличить `N` в 2 раза, время должно вырасти примерно в 8 раз:

```text
2³ = 8
```

Если увеличить `N` в 10 раз, время должно вырасти примерно в 1000 раз:

```text
10³ = 1000
```

---

### 2. Ускорение при увеличении количества потоков

При увеличении количества потоков время выполнения уменьшается, однако ускорение обычно меньше идеального.

Идеальное ускорение для `p` потоков:

```text
S(p) = p
```

На практике:

```text
S(p) < p
```

Это объясняется несколькими причинами:

- накладные расходы на создание и синхронизацию потоков;
- ограничение пропускной способности памяти;
- конфликты кэш-линий;
- неравномерная загрузка ядер;
- фоновые процессы операционной системы;
- троттлинг процессора при длительной нагрузке;
- использование логических потоков вместо физических ядер.

---

### 3. Малые размеры матриц

На малых матрицах, например `N = 200`, параллельная версия может давать небольшое ускорение или даже работать сопоставимо с последовательной.

Это связано с тем, что накладные расходы OpenMP становятся заметной частью общего времени выполнения.

---

### 4. Большие размеры матриц

На больших матрицах, например `N = 1200` или `N = 2000`, параллельная версия обычно показывает более заметное ускорение.

Это объясняется тем, что полезная вычислительная нагрузка становится значительно больше накладных расходов на распараллеливание.

---

### 5. Эффективность параллельного выполнения

Эффективность показывает, насколько рационально используются потоки:

```text
E(p) = S(p) / p
```

Если эффективность близка к 1, потоки используются хорошо.

Если эффективность заметно меньше 1, добавление новых потоков даёт меньший прирост производительности.

Для данной задачи ожидаемо, что эффективность снижается при увеличении количества потоков, особенно на фоне ограничения по памяти и использования логических ядер.
