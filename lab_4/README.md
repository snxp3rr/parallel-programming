## Используемая задача

В качестве экспериментальной задачи используется операция перемножения двух квадратных матриц:

```text
C = A × B
```

где:

- `A` — матрица размера `N × N`;
- `B` — матрица размера `N × N`;
- `C` — результирующая матрица размера `N × N`.

Классический алгоритм умножения матриц имеет асимптотическую сложность:

```text
O(N³)
```

Количество арифметических операций приблизительно равно:

```text
2*N³ - N²
```

то есть:

- `N³` умножений;
- `N² × (N - 1)` сложений.

---

## CUDA-модель выполнения

В CUDA вычисления организованы по схеме:

```text
grid -> blocks -> threads
```

Для умножения матриц используется двумерная сетка блоков и двумерные блоки тем.

Каждая тема CUDA вычисляет один элемент результирующей матрицы:

```text
C[row][col]
```

Если размер блока равен `tile × tile`, то:

```text
blockDim.x = tile
blockDim.y = tile
```

Количество блоков по горизонтали и вертикали вычисляется как:

```text
gridDim.x = ceil(N / tile)
gridDim.y = ceil(N / tile)
```

Координаты элемента матрицы, который обрабатывает текущая тема:

```text
row = blockIdx.y * blockDim.y + threadIdx.y
col = blockIdx.x * blockDim.x + threadIdx.x
```

Если `row < N` и `col < N`, тема вычисляет значение `C[row][col]`.

## Используемые CUDA-ядра

В ходе расчётов была использована только Tiled Kernel. Хоть от Naive Kernel он и отличается принципом работы, затраченное время на решение задачи у них варьируется в пределах погрешности.

---

Tiled-ядро использует shared memory для хранения небольших фрагментов матриц `A` и `B`.

Идея состоит в том, что блок тем загружает в shared memory два тайла:

- фрагмент строки матрицы `A`;
- фрагмент столбца матрицы `B`.

Затем темы внутри блока вычисляют частичные суммы, используя быстрые обращения к shared memory.

Это уменьшает количество обращений к глобальной памяти и обычно даёт заметный прирост производительности.

В программе используется вариант с квадратным блоком:

```text
tile × tile
```

Например:

```text
8 × 8
16 × 16
32 × 32
```

Размер блока `32 × 32` соответствует 1024 темам, что обычно является максимальным размером блока для многих GPU.

## Особенности реализации

Программа лабораторной работы №4 использует обычные C++ заголовки, а не `import std`, потому что CUDA-компилятор `nvcc` и экспериментальная поддержка модулей C++23 могут некорректно работать вместе.

Для CUDA-цели в CMake используется C++17:

```cmake
CUDA_STANDARD 17
CXX_STANDARD 17
```

Время выполнения измеряется не через `std::chrono`, а через CUDA events:

```cpp
cudaEventRecord(start_event);

// запуск CUDA-ядра

cudaEventRecord(stop_event);
cudaEventSynchronize(stop_event);
cudaEventElapsedTime(&milliseconds, start_event, stop_event);
```

Это позволяет измерить время выполнения именно GPU-ядра, без учёта времени чтения файлов и копирования данных между CPU и GPU.

## Пояснение полей отчёта(будут описаны только новые)

### `kernel`

Используемое CUDA-ядро.

Возможные значения:

```text
naive
tiled
```

- `naive` — простое ядро без shared memory;
- `tiled` — оптимизированное ядро с использованием shared memory.

---

### `device`

Название GPU, на котором выполнялся расчёт.

Пример:

```text
device=NVIDIA GeForce RTX 5060
```

---

### `tile`

Размер квадратного блока CUDA по одной координате.

Например:

```text
tile=16
```

означает блок размером:

```text
16 × 16
```

Количество тем в таком блоке:

```text
16 * 16 = 256
```

---

### `block_x`, `block_y`

Размеры блока CUDA по осям X и Y.

Для квадратного блока:

```text
block_x = tile
block_y = tile
```

---

### `grid_x`, `grid_y`

Размеры сетки блоков CUDA.

Вычисляются как:

```text
grid_x = ceil(N / tile)
grid_y = ceil(N / tile)
```

Например, для `N = 200` и `tile = 16`:

```text
grid_x = ceil(200 / 16) = 13
grid_y = ceil(200 / 16) = 13
```

То есть всего используется:

```text
13 × 13 = 169 блоков
```

## Анализ результатов

### 1. CUDA сохраняет кубическую сложность алгоритма

Как и в последовательной версии, общее количество операций не меняется:

```text
2*N³ - N²
```

CUDA не изменяет асимптотическую сложность алгоритма, но позволяет распределить вычисления между большим количеством потоков выполнения на GPU.

Поэтому время выполнения всё равно растёт примерно как:

```text
O(N³)
```

но с существенно меньшей константой за счёт массового параллелизма.

---

### 2. Размер блока влияет на производительность

Размер блока определяет компромисс между несколькими факторами.

Маленькие блоки, например `8 × 8`:

- создают больше блоков;
- могут лучше использовать распараллеливание;
- но увеличивают накладные расходы на управление блоками;
- хуже используют shared memory для повторного применения данных.

Большие блоки, например `32 × 32`:

- содержат больше тем;
- лучше используют shared memory;
- уменьшают количество блоков;
- но могут снижать occupancy, если для блока требуется много ресурсов.

Поэтому оптимальный размер блока обычно лежит в середине диапазона, например:

```text
16 × 16
```

или

```text
32 × 32
```

Конкретный лучший вариант зависит от GPU.

---

### 3. Малые матрицы дают меньший speedup

На матрицах размера, например, `200 × 200`, GPU может не успеть полностью раскрыть свой потенциал.

Это связано с тем, что заметную роль начинают играть:

- время запуска CUDA-ядра;
- копирование данных из host-памяти в device-память;
- обратное копирование результата;
- недостаточное количество работы для тысяч потоков GPU.

Поэтому speedup на малых матрицах обычно меньше, чем на больших.

---

### 4. Большие матрицы лучше показывают преимущество GPU

На матрицах размера `1200 × 1200`, `1600 × 1600` и `2000 × 2000` объём вычислений становится достаточно большим, чтобы GPU смог эффективно использовать массовый параллелизм.

В этом случае CUDA-версия обычно показывает значительное ускорение относительно последовательной CPU-версии.

## Корректность вычислений

Корректность CUDA-реализации проверялась автоматически с помощью Python и NumPy.

Для каждого размера матрицы и каждой конфигурации блока выполнялось сравнение:

```python
np.array_equal(C, A @ B)
```

Если результат совпадает полностью, выводится:

```text
OK
```

Если есть хотя бы одно отличие, выводится:

```text
FAIL
```

Так как используются целые числа, сравнение является точным и не требует допуска погрешности.

Во всех проведённых экспериментах результат верификации:

```text
OK
```

Это подтверждает, что CUDA-реализация корректна и не содержит ошибок индексации, гонок данных или проблем с синхронизацией тем внутри блока.

В ходе лабораторной работы была реализована и исследована параллельная версия умножения квадратных матриц с использованием CUDA.

2. Проведена серия экспериментов для размеров матриц:

   ```text
   200, 400, 800, 1200, 1600, 2000
   ```

3. Исследовано влияние размера блока CUDA:

   ```text
   8 × 8
   16 × 16
   32 × 32
   ```

   - время выполнения CUDA-ядра;

   - ускорение относительно последовательной CPU-версии.

   ```text
   O(N³)
   ```

6. Установлено, что оптимальный размер блока зависит от размера матрицы и архитектуры GPU.
