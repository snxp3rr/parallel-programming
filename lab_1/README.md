# Лабораторная работа №1: Последовательное умножение квадратных матриц

## Цель работы

Получить данные о производительности последовательного алгоритма умножения квадратных матриц для последующего сравнения с параллельными реализациями.

В первой лабораторной работе используется один поток выполнения.

---

## Используемая задача

В качестве экспериментальной задачи выбрана операция перемножения двух квадратных матриц:

```text
C = A × B
```

где:

- `A` — матрица размера `N × N`;
- `B` — матрица размера `N × N`;
- `C` — результирующая матрица размера `N × N`.

Классический алгоритм умножения матриц имеет асимптотическую сложность:

```text
O(N³)
```

Количество арифметических операций приблизительно равно:

```text
2*N³ - N²
```

то есть:

- `N³` умножений;
- `N² * (N - 1)` сложений.

## Формат исходных матриц

Каждая входная матрица хранится в текстовом файле.

Первая строка — количество элементов в строке, то есть сторона квадратной матрицы `N`.

Далее идут `N` строк, каждая содержит `N` целых чисел.

Пример для матрицы `3x3`:

```text
3
1 -2 3
4 5 -6
7 8 9
```

Имена файлов генерируются автоматически по размеру матрицы:

```text
A_20.txt
B_20.txt

A_100.txt
B_100.txt

A_250.txt
B_250.txt
```

и так далее.

Значения элементов выбираются случайно из диапазона:

```text
[-100, 100]
```

---

## Формат результирующего файла

Результирующий файл содержит сначала отчёт, затем разделитель, затем саму матрицу.

Пример структуры файла `C_20.txt`:

```text
N=20
time_seconds=0.000123
time_ms=0.123
integer_operations=15600
memory_bytes=4800
gops=0.1268
a_file=extra/matrices/A_20.txt
b_file=extra/matrices/B_20.txt
output_file=extra/res/C_20.txt
--- MATRIX ---
20
...
```

## Пояснение полей отчёта

### `N`

Количество элементов в строке результирующей матрицы.

Общее количество элементов в матрице:

```text
N²
```

---

### `time_seconds`

Время выполнения операции умножения матриц в секундах.

Замеряется только время функции умножения, без времени чтения входных файлов и записи результата.

---

### `time_ms`

То же время, но в миллисекундах:

---

### `integer_operations`

Теоретическое количество целочисленных операций, выполняемых классическим алгоритмом умножения матриц.

Для одной ячейки результата требуется:

- `N` умножений;
- `N - 1` сложений.

---

### `memory_bytes`

Приблизительный объём данных задачи в байтах.

---

### `gops`

GOPS — Billion Operations Per Second, то есть количество операций в миллиардах в секунду.

---

### `a_file`

Путь к файлу с первой исходной матрицей `A`.

---

### `b_file`

Путь к файлу со второй исходной матрицей `B`.

---

### `output_file`

Путь к файлу, в который записан результат.

## Ход работы

### 1. Генерация исходных матриц

Программа `extra/src/main.cpp` создаёт две случайные квадратные матрицы `A` и `B`.

Размер матрицы задаётся аргументом командной строки:

```bash
./build/extra/MatrixGenerator 20
```

Можно также задать seed для воспроизводимости:

```bash
./build/extra/MatrixGenerator 20 12345
```

Генерация использует:

```cpp
std::mt19937_64 rng(seed);
std::uniform_int_distribution<int> dist(-100, 100);
```

В результате создаются файлы:

```text
extra/matrices/A_20.txt
extra/matrices/B_20.txt
```

---

### 2. Чтение матриц

Основная программа `lab_1/src/main.cpp` читает матрицы из файлов.

Функция чтения получает:

- путь к файлу;
- переменную для стороны матрицы `n`;
- одномерный `std::vector<int>`, в который матрица сохраняется построчно.

Логика чтения:

```cpp
std::ifstream in(path);

in >> n;

const std::size_t total = n * n;
data.resize(total);

for (std::size_t i = 0; i < total; ++i)
{
    in >> data[i];
}
```

Поскольку `std::vector` одномерный, двумерная матрица хранится в row-major порядке:

```text
index(i, j) = i * N + j
```

То есть элемент строки `i` и столбца `j` находится по индексу:

```cpp
data[i * n + j]
```

---

### 3. Умножение матриц

Используется классический алгоритм умножения матриц.

Формально:

```text
C[i][j] = sum_{k=0}^{N-1} A[i][k] * B[k][j]
```

В одномерном представлении:

```text
C[i*N + j] += A[i*N + k] * B[k*N + j]
```
---

### 4. Замер времени

Время измеряется с помощью:

```cpp
std::chrono::steady_clock
```

Замер выполняется только вокруг функции умножения:

```cpp
const auto start = std::chrono::steady_clock::now();

multiply_matrices(A, B, C, n);

const auto finish = std::chrono::steady_clock::now();

const std::chrono::duration<double> elapsed = finish - start;
const double seconds = elapsed.count();
```

Это позволяет получить чистое время вычисления, не смешивая его с временем открытия файлов, чтения текста и записи результата.

---

### 5. Верификация через Python и NumPy

Скрипт `scripts/verify_numpy.py` читает:

- матрицу `A`;
- матрицу `B`;
- матрицу `C`, полученную в C++ программе.

Затем вычисляет эталонное произведение:

```python
C_ref = A @ B
```

и сравнивает его с результатом C++ программы:

```python
ok = np.array_equal(C, C_ref)
```

Запуск проверки:

```bash
python3 scripts/verify_numpy.py 20
```

где `20` — количество элементов в строке матрицы.

## Анализ результатов

После проведения экспериментов нужно проверить, выполняется ли ожидаемая зависимость:

```text
T(N) = O(N³)
```

Основные признаки кубической зависимости:

1. Если увеличить `N` в 2 раза, время должно вырасти примерно в 8 раз:

   ```text
   2³ = 8
   ```

2. Если увеличить `N` в 10 раз, время должно вырасти примерно в 1000 раз:

   ```text
   10³ = 1000
   ```

3. На больших размерах матриц время может отклоняться от идеальной кубической зависимости из-за:
   - кэш-промахов;
   - ограниченной пропускной способности памяти;
   - фоновых процессов ОС;
   - троттлинга процессора;
   - особенностей компилятора и флагов оптимизации.

## Корректность вычислений

Корректность последовательной реализации проверялась автоматически с помощью Python и NumPy.

Для каждого размера матрицы выполнялось сравнение:

```python
np.array_equal(C, A @ B)
```

Если результат совпадает полностью, выводится:

```text
OK
```

Если есть хотя бы одно отличие, выводится:

```text
FAIL
```

Так как используются целые числа, сравнение является точным и не требует допуска погрешности.
